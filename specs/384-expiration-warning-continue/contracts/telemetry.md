# Verification Telemetry Contract: Warn Before Expiration and Continue Accessibly Across Tabs

**Plan**: [plan.md](../plan.md)

**Feature verification**: [verification.md](../verification.md)

**Module contracts**: [modules.md](modules.md)

**Status**: Planned design. No instrumentation exists until an implementation slice adds it.

This contract designs the runtime telemetry a verification agent needs for the feature's claims. It follows the
[verification telemetry conventions](../../../docs/observability.md#verification-telemetry-conventions) and the
[verification harness](../../../docs/engineering/verification-harness.md). Instrumentation listed here is committed
product code. Durable tests do not assert it.

Existing signals are reused, not redefined: the [session-state signals](../../../docs/session-state.md#verification-signals)
(`protectRequest`, `SessionService.*`, `sessionActivity`, `sessionStatus`, and the tenant configuration log) and the
[browser harness facts](../../../docs/observability.md#browser-harness-facts) (`TabCoordination.transition`,
`TabChannel.*`, `Focus.move`).

`RUN` stands for `resource.service.version = "<sha>" && resource.service.instance.id = "<run-uuid>"`. Every verifier
query filters by both run resource attributes. Spans may also correlate by trace context, `session.id`, and
`preets.tenant.alias`. Browser facts carry no `session.id` or tenant. Relate them to server spans by run, order, and
`preets.session.deadline_ms`.

Browser records T-001 to T-004 are exported only when browser tracing runs (protected `(app)` documents with
`BROWSER_TRACING_ENABLED=true`). The new span names `TabCoordination.threshold` and `Interaction.continue` and the
new attribute key `preets.session.warning_lead_minutes` are added to `shared/browser-tracing/export-filter.ts` in
slice A.

### Outcome values

| Signal | `preets.outcome` values and meaning                                                                                                                                    |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-001  | `reached`: the tab reached its local threshold, or resumed past it, and starts its confirmation. The only value.                                                       |
| T-002  | `applied` (unchanged for transitions).                                                                                                                                 |
| T-003  | `activated`: the user activated Continue and the tab sent the request. The only value. Absence means no Continue was sent.                                             |
| T-004  | `moved` (unchanged).                                                                                                                                                   |
| T-005  | Unchanged set (`renewed`, `unchanged`, `expired`, `missing`, `no_reference`, `tenant_mismatch`, `unavailable`). With `continue-session`, `unchanged` is not reachable. |

New closed sets and values introduced here, each reachable:

| Attribute                        | Values and how each is reached                                                                                                                                                                                             |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `preets.ui.to_state` (added)     | `warning_shown`: a confirmed warning period in an active, unconcealed tab.                                                                                                                                                 |
| `preets.ui.cause` (added)        | `threshold`: confirmation at the local threshold. `continue`: this tab's Continue renewed. `renewal`: another answer this tab received showed a renewal. `resume` and `peer` keep their meaning and now apply to warnings. |
| `preets.focus.target` (added)    | `warning_continue`: the Continue button.                                                                                                                                                                                   |
| `preets.session.activity` (HTTP) | `continue-session`: a Continue request the handler admitted.                                                                                                                                                               |

## Verifier environment

- Standard harness environment: `OTEL_SERVICE_VERSION=<sha>`, `OTEL_RESOURCE_ATTRIBUTES` including
  `service.version=<sha>,service.instance.id=<run-uuid>`, `BROWSER_TRACING_ENABLED=true` for browser-telemetry steps,
  a `preets:verify:<run-uuid>:` Redis prefix, and owned ports.
- A scratch tenant directory copied from the tracked fixtures. Springfield with `idleTimeoutMinutes: 5` and
  `warningLeadMinutes: 4` puts the threshold one minute after each renewal. Other settings per quickstart section.
- Real elapsed time for thresholds (research D13). Playwright clock control only to suspend or skew one tab, and
  request routing to fail or delay one Continue (research D14). Each is recorded as a condition.
- Export delays: about 30 s for traces. Keep each page open 30 s after its last sampled step, and wait for
  `data-preets-browser-tracing="started"` before sampled steps.
