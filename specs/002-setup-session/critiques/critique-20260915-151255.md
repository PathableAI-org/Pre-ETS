Remaining findings are recommendations and clarifying questions; architecture does not need a rethink.

Suggested concrete edits for must-address and key recommendations:

### `spec.md` — Lifecycle assumption (P5)

Replace the Lifecycle default assumption with:

> **Lifecycle decision (approved)**: Use a configurable fixed lifetime defaulting to 24 hours (86,400 seconds) from creation, with no sliding renewal in this increment. The record and cookie expire together; earlier record loss starts a fresh session.

### `spec.md` — Edge Cases (P4)

Add:

> - When session storage is unavailable, requests may receive the controlled service failure before host/tenant validation completes; invalid hosts are not guaranteed an Access denied response until storage recovers.

### `plan.md` / `contracts/session-setup.md` — Compatibility (E1)

Add supersession text along the lines of:

> **Supersedes** `specs/001-tenant-resolution/contracts/tenant-context.md` Refusal guidance for Proxy-matched participating routes (`/`): those routes MAY terminate invalid-host / unknown-tenant / configuration failures in Proxy with the same visible outcomes (`Access denied.` / static-mode guidance / generic 500). Layout-only `forbidden()` remains valid for non-participating routes until they join the matcher. Implementation MUST update the 001 Refusal paragraph in the Proxy/SSR slice and keep dual-layer regression coverage.

### `plan.md` — Rollback + observability (P6, E8)

Add under Delivery Sequence:

> **Rollback**: If session setup 503s block tenant pages after enablement, revert the Proxy/session integration; Redis Compose may remain. **Observability**: Log/metric only safe outcome classes (reuse, create, 403, 500, 503)—never secrets, raw cookies, or session ids.
