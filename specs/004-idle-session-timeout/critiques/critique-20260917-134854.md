## Executive Summary

The spec and plan are strong on the hard security core: Redis-authoritative idle deadlines,
fail-closed invalid policy, cause accuracy (FR-008), tenant isolation, absolute-lifetime
preservation, PathAble Modal ownership, and a bounded protected-op inventory grounded in the
existing OIDC callback + Proxy session path. Phase 0–1 artifacts are coherent with drafted
Gherkin and constitution ownership.

The primary gap is recovery UX while the application is **running**: Gherkin and FR-009 require
a confirmed-inactivity modal (and protected-content removal) when access expires with the app
able to update, but research/plan frame client timers as optional “complementary UX.” That leaves
implementers free to ship server-only denial that never surfaces the modal until a later
navigation—failing `idle-session-recovery.feature` (“while the application is running”). Pin a
mandatory client revalidation path (still non-authoritative) before `/speckit.tasks`. Secondary
gaps (pin cause-signal storage, session parser shape migration, observability, stale 003
assumption wording) are recommendations and do not block once the running-app recovery path is
specified.
